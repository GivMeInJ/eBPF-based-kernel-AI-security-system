# 이벤트 시각 기반 모델과 행동 기억 실험

기존 bucket-data9 모델의 학습·추론 불일치를 바로잡고, 정상 관리 작업의 오탐과 공격 모사의 미탐을 줄이기 위한 실험이다. 이 실험은 ADFA-LD syscall 빈도 모델과 별개이며, 비교 대상은 [bucket-data9의 RandomForest](../bucket-data9/README.md)다.

**우선 목표는 학습하지 않은 공격 유형의 탐지율을 높이는 것이다. 이번 공격 그룹 제외 평가에서는 이 목표를 충족하지 못했다.** V2의 기존 유형 DR 99.2537%는 새로운 공격 유형의 탐지 성능을 입증하지 않는다. [사전 계획](unseen_attack_run_plan.json)에 따른 [실제 그룹 제외 결과](results/unseen_group_evaluation_20261006.json)를 아래 핵심 결과로 기록한다.

V2는 새 시험 세션의 389개 버킷에서 탐지율 99.2537%, FPR 0%를 기록했다. **같은 시험셋에서 V1도 같은 결과였으므로 V2가 V1보다 좋아졌다고 주장하지 않는다.** 과거 V1 시험의 FPR 2.0%와 목표 0.5% 실패 기록은 그대로 보존한다. 별도 행동 probe는 실제 600초 대기와 두 episode 연결을 확인했다. 어느 결과도 실제 침해 탐지율이나 운영 FPR을 입증하지 않는다.

**V1 기준 모델의 기존 shadow 감시는 유지하고, V2는 오프라인 결과물로만 보존한다.** 알려진 유형에서 V1·V2가 동률이고 핵심 미학습 탐지 목표를 충족하지 못했으므로 새 V2 shadow 감시를 추가하지 않는다.

## 핵심 결과: 미학습 공격 그룹 탐지 목표 미달

학습에서 공격 의미 그룹 전체를 제외한 뒤, 해당 그룹을 새 시험 세션에서 평가했다. 고정된 기존 학습 세션 ID 순서에서 앞의 두 세션을 사용하는 조건과 네 세션 모두를 사용하는 조건을 비교했다. **각 조건에서 그룹별 진단용 RandomForest 네 개씩을 따로 재학습했다. 이는 저장된 `candidates/v1/` 또는 `candidates/v2/` 모델의 미학습 공격 DR이 아니다.** 결과 JSON의 `v1_like_first2`, `v2_like_all4`는 학습 데이터 양을 구분하는 조건 이름이다. 진단 모델은 export하거나 배포하지 않았다.

모든 진단 모델은 26개 특징·300개 트리·`random_state=42`·`class_weight="balanced"`를 유지했다. 각 모델의 학습에서 해당 그룹의 양성 버킷을 모두 제외했고, 새 보정 세션의 정상 254개 버킷만으로 목표 FPR 0.5%의 임계값을 정했다. 보정 양성 134개는 사용하지 않았다. 시험은 같은 새 시험 세션의 정상 255개 버킷과 해당 제외 그룹의 양성 버킷으로 구성했다. 시험 점수에 맞춰 특징·임계값·그룹 구성을 바꾸지 않았다. 세부 분할·제외 확인·임계값은 [결과 JSON](results/unseen_group_evaluation_20261006.json)에 보존돼 있다.

| 제외한 의미 그룹과 양성 모사 라벨 | 학습 2세션 DR (TP/양성) | 학습 4세션 DR (TP/양성) | 학습 4세션 FPR (FP/정상) |
| --- | ---: | ---: | ---: |
| 유출: `bulk_exfil`, `dns_exfil` | 0% (0/6) | 100% (6/6) | 1.176% (3/255) |
| 파일 파괴: `ransom_sim`, `wiper_sim` | 0% (0/64) | 0% (0/64) | 0.392% (1/255) |
| 원격 셸: `reverse_shell` | 0% (0/3) | 100% (3/3) | 0% (0/255) |
| 자원 남용: `resource_hijack` | 0% (0/61) | 0% (0/61) | 0% (0/255) |

학습 2세션 조건은 네 그룹 모두 DR 0%였고, 각 진단 모델의 시험 FPR도 0%였다. 4세션 조건에서 관측된 개선은 유출 6개·원격 셸 3개 버킷이라는 작은 두 그룹에 한정됐다. 유출 모델의 시험 FPR 1.176%는 목표 0.5%를 넘었다. 파일 파괴 64개와 자원 남용 61개는 각각의 그룹 제외 모델에서 **합계 125개 버킷 모두 미탐**이었다. 따라서 미학습 공격 유형을 폭넓게 탐지한다는 핵심 목표는 달성하지 못했다.

각 행은 서로 다른 모델의 결과다. 정상 255개 버킷은 행마다 같은 자료를 다시 평가한 것이므로 분모를 합쳐 운영 FPR로 보고하지 않는다. 그룹별 탐지 건수를 합쳐 단일 모델의 DR로 보고하지도 않는다. 작은 두 그룹의 100%를 일반적인 미지 공격 탐지율로 해석하지 않는다.

계획은 V2의 기존 유형 결과를 본 뒤, 그룹 제외 점수를 산출하기 전에 정했다. 특징 설계에는 기존 개발·연구 경험이 반영됐고 이미 살펴본 세션을 사용했으므로 완전히 손대지 않은 블라인드 시험은 아니다. 제한된 로컬·더미 모사 그룹, 한 시험 세션, 서로 연관된 소수 버킷이라는 한계가 있다. 실제 미지의 침해나 zero-day 탐지율을 입증하지 않는다.

### 정상 전용 모델 비교 — 탐지 개선 없음

[고정 조건](results/normal_only_protocol_20261006.json)으로 기존 26개 버킷 특징에 IsolationForest를 실제 학습했다. 학습에는 앞 두 세션의 정상 513개 또는 네 세션의 정상 1,016개만 사용했고, 모든 공격을 제외했다. 별도 보정 세션의 정상 254개만으로 목표 FPR 0.5%의 임계값을 정했다. 같은 시험 세션의 정상 255개·공격 134개를 평가했다. 트리 300개와 seed 42 등 조건을 고정했고, 시험 결과로 임계값을 조정하지 않았다.

| 정상 전용 학습 조건 | TP | FN | FP | TN | DR | FPR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 앞 두 세션 | 0 | 134 | 1 | 254 | 0% | 0.392% |
| 네 세션 | 0 | 134 | 1 | 254 | 0% | 0.392% |

[실측 결과와 입력·코드 해시](results/normal_only_evaluation_20261006.json)를 보존한다. 두 조건 모두 네 공격 그룹을 전부 놓쳤다. 현재 특징과 조건에서는 알고리즘 교체만으로 미학습 공격 탐지를 개선하지 못했다. 이미 살펴본 자료의 개발 실험이며, IsolationForest 전체가 효과 없다는 결론이나 실제 미지 공격 성능으로 일반화하지 않는다. 모델은 export하거나 운영에 적용하지 않았다.

[후속 계획](results/normal_only_followup_plan_20261006.json)은 행동 정보의 부족을 먼저 확인하도록 정했다. 채택된 시험 캡처에는 현재 모델이 활용하지 않는 `FILE_UNLINK` 이벤트 23,082건이 있다. 기존 원본을 재분석해 삭제 **시도**의 양과 디렉터리 식별자 범위를 확인한다. 현재 unlink 센서는 basename과 partial-path 플래그를 제공하므로 이를 전체 경로로 해석하지 않으며, hook 관측을 삭제 성공으로 해석하지 않는다. CPU 사용량과 역할별 정상 기준은 현재 자료만으로 검증할 수 없다.

[원본 재분석 결과](results/unlink_bucket_audit_20261006.json)는 23,082건 모두 기존 시험의 389개 버킷에 연결됐고, 버킷 밖 이벤트와 알 수 없는 디렉터리 범위는 각각 0건임을 기록한다. 파일 파괴 모사의 64개 버킷 중 63개에서 삭제 시도가 있었지만, 정상 작업에도 삭제가 있었다. 정상 `w_zip`은 한 버킷 최대 8,312건, `w_tar`는 5,336건이었고, `ransom_sim`은 최대 105건, `wiper_sim`은 58건이었다. 정상 `w_tar`의 디렉터리 범위도 최대 1,479개로 모사의 1개보다 넓었다. **삭제량·범위가 크다는 이유만으로 공격으로 판정하는 규칙은 이 대조군을 구분하지 못한다.**

이 재분석은 새 특징 후보의 개발 근거이며 탐지 모델의 성능 측정이 아니다. 다음 단계에서는 반복·지속된 변화와 정상 작업의 역할·맥락을 함께 표현하고, 그 규칙을 고정한 뒤 새 데이터로 검증해야 한다. 현재 시험의 시간 길이·기법 이름에 맞춘 경보 규칙을 만들거나, 단일 센서 관측으로 사용자 의도를 판정하지 않는다.

### 파일 변화의 시간 특징 — 구현 및 개발 비교 완료, 적용 보류

[실행 전 계획](results/temporal_unlinks_plan_20261006.json)에 따라 [공유 계산 코드](src/temporal_unlinks.py)를 추가했다. 현재 삭제 시도량·디렉터리 범위와 5·30·60초의 삭제 시도 합계·활동 초 비율 등 8개 특징을 계산한다. 각 시간창은 현재 1초 버킷과 이전 `W−1`초만 포함하며, 현재 버킷이 닫힌 뒤 평가하는 방식이다. 미래 이벤트는 과거 특징을 바꾸지 않는다. 세션 안의 유닛·라벨 경계에서 이력을 초기화하지 않는다. 범위는 수집된 cgroup 전체이며, 같은 task나 검증된 프로세스 계보라고 주장하지 않는다.

기존 6개 압축 원본의 체크섬을 확인하고 버킷 ID·세션·라벨을 정확히 연결했다. [6개 재분석 결과와 수집 품질 검증](results/temporal-unlinks/)을 보존한다. 실제 이벤트 유실은 모두 0이고, 선택적 socket metadata 누락은 별도로 유지한다. 59초의 준비 구간을 제외했으며, 정상 전용 학습·보정에는 과거 60초에 양성 공격 버킷이 섞이지 않은 정상 행만 썼다. 공격 그룹 제외 RF는 해당 그룹의 과거 흔적을 포함한 모든 학습 행도 제외했다. **시험 정상 행은 이전 공격 흔적이 있다는 이유로 제거하지 않았다.**

기존 26개 특징과 추가된 34개 특징은 같은 행·순서·고정 모델 조건을 사용했다. 정상 전용 학습에는 정상 259개, 보정에는 정상 59개가 남았다. 시험은 준비 구간의 정상 42개·양성 2개를 제외한 정상 213개·양성 132개다. 보정 정상만으로 목표 FPR 0.5%의 임계값을 정했다. 59개 보정 정상에서 오탐 1개는 약 1.69%이므로 이 표본 수로 작은 운영 FPR을 입증할 수 없다.

| 제외 공격 그룹 | 26개 특징 TP/양성 | 34개 특징 TP/양성 | 26개 특징 FP/정상 | 34개 특징 FP/정상 |
| --- | ---: | ---: | ---: | ---: |
| 유출 | 4/4 | 4/4 | 8/213 | 29/213 |
| 파일 파괴 | 0/64 | 9/64 | 3/213 | 23/213 |
| 원격 셸 | 3/3 | 3/3 | 5/213 | 17/213 |
| 자원 남용 | 0/61 | 0/61 | 0/213 | 0/213 |

각 행은 서로 다른 진단용 RF다. 파일 파괴 모사 DR은 0%에서 14.0625%로 올랐지만 FPR도 약 1.408%에서 10.798%로 늘었다. 다른 두 그룹에서도 오탐이 늘었다. 정상 전용 IsolationForest는 두 특징 조건 모두 TP 0·FN 132·FP 0·TN 213으로 공격을 전부 놓쳤다. **미학습 탐지와 낮은 오탐을 함께 달성하지 못했으므로 모델을 export하거나 운영에 적용하지 않았다.** 이전 평가와는 학습·보정·시험 행이 달라 직접 개선 수치로 비교하지 않는다.

[결과 JSON](results/temporal-unlinks/evaluation.json)에는 첫 결과를 본 뒤 추가한 오탐 맥락 분해도 있다. 학습·보정·시험 행과 모델 조건을 바꾸지 않고 보고 항목만 추가했으며, 원래 임계값과 평가 집계가 같은지 확인했다. 시험 정상 213개 중 과거 60초에 양성 공격 버킷이 없는 정상은 106개, 공격 이력과 겹친 정상은 107개다. 파일 파괴 진단의 추가 특징 모델은 각각 10개·13개를 오탐했다. 따라서 오탐 증가는 이전 공격 이력이 남는 문제만으로 설명할 수 없다. 이 사후 분석을 이유로 시험 행을 제거하거나 임계값을 튜닝하지 않았다.

이는 이미 살펴본 모사 자료의 개발 실험이다. 60초 특징은 더 긴 `sleep` 대응을 입증하지 않으며, 기존의 600초 계보 probe와 별개다. 역할별 정상 기준, CPU 특징의 모델 통합, 파일 변화의 task 계보별 연결, 새 공격군 블라인드 시험은 아직 완료되지 않았다. 다음 단계는 서로 다른 작업의 이력을 섞지 않는 식별자·역할 정보를 확보하고, 정상 정리 작업 및 공격 후 정상 작업을 대조군으로 유지하는 것이다.

CPU 입력을 확보하기 위해 [읽기 전용 수집 코드](src/sample_cgroup_cpu.py)도 추가했다. [3초 실제 파일럿](results/temporal-unlinks/cpu_pilot.jsonl)은 `trainset`, `cron`, Docker daemon, containerd daemon의 네 cgroup에서 12개 유효 구간과 완료 기록을 남겼다. 누적 `cpu.stat` 차이와 실제 경과 시간으로 평균 사용 코어 수를 계산하며, cgroup 교체·카운터 초기화·잘못된 시간 간격은 오류로 기록하고 중단한다. 역할은 설정된 감시 범위이며 **정상/공격 라벨이 아니다**. Docker/containerd daemon 관측이 모든 컨테이너 작업을 포함한다고 주장하지 않는다. CPU는 cgroup의 하위 작업을 포함하며, 개별 task CPU나 eBPF 시각과의 정렬은 아직 검증하지 않았다. CPU 수집 파일럿의 성공을 자원 남용 탐지 성능으로 해석하지 않는다.

[30분 수집 실행 기록](results/temporal-unlinks/cpu_collection_run.json)에 따라 서버에 1초 간격의 제한된 CPU 관측도 시작했다. 데이터는 `/whs/cgroup_cpu_roles_20261006.jsonl`, 오류 로그는 `/whs/cgroup_cpu_roles_20261006.log`에 남긴다. 확인 당시 실행 중이었으며, 이 기록이 현재의 실시간 상태를 보장하지는 않는다. 반복 일정이나 자동 AI 점검·알림은 추가하지 않았다. 모델·경보 정책은 그대로 유지한다.

[완료 검증](results/temporal-unlinks/cpu_collection_complete.json)에서는 네 역할 각각 1,795개 연속 구간과 약 1,800초의 관측, 완료 마커, coverage 오류 0건을 확인했다. `trainset` CPU는 전 구간 0이었다. 이 자료에는 승인 여부나 공격 라벨이 없으므로 정상 고부하 학습 자료로 쓰지 않는다.

### CPU 승인 맥락 대조 실험

[실험 코드](src/probe_cpu_context.py)는 동일 역할에서 같은 계산을 승인·미승인으로 설정한 합성 대조군을 만든다. 라벨은 외부 실험 계획의 승인 정책이며 실제 악성 의도가 아니다. 작업에 라벨을 전달하지 않고 CPU 사용량만 측정한다. SHA256, PBKDF2, 정수 계산을 서로 다른 개발·보정·시험 쌍으로 고정하고 각 조건을 역순으로도 실행한다. 개발 쌍에서는 모델을 학습하지 않으며, 승인 보정 쌍 두 개의 최대 CPU 점수 바로 위를 임계값으로 사용한다. 시험 결과로 임계값을 바꾸지 않는다.

수집은 새로운 전용 cgroup의 반 코어 제한과 episode별 10초 계산으로 한정한다. 작업의 cgroup 진입·CPU quota·시작 확인과 부모의 시간 제한, 종료 신호에 대한 작업 정리를 검사한다. 유효 CPU 부하와 시간 범위를 충족하지 않으면 완료 평가를 거부한다. 이 대조 실험은 CPU만 사용하는 기준의 한계를 확인하기 위한 것이며, 실제 자원 남용 공격이나 일반적인 미학습 공격 탐지율 평가를 대신하지 않는다. 정상 보정·시험 표본이 각각 두 개뿐이므로 낮은 운영 FPR을 보장할 수 없다.

[실측 결과](results/cpu-context/evaluation.json)는 시험의 미승인 모사 두 개 중 TP 1·FN 1, 승인 두 개 중 FP 1·TN 1이었다. 합성 정책 라벨에 대한 검출 비율과 FPR은 각각 50%이며, **이 수치를 실제 공격 탐지율로 보고하지 않는다**. 최초 예비 실행은 시작·정리 보장이 부족해 제외하고, 수정 후 새 실행의 12개 episode만 사용했다. [측정값](results/cpu-context/episodes.jsonl), [구간 기록](results/cpu-context/intervals.jsonl), [고정 계획](results/cpu-context/protocol.json), [종료 검증](results/cpu-context/termination_verification.json)을 보존한다. 별도의 [다음 데이터 요건](results/cpu-context/followup_plan.json)은 검증된 task 계보와 CPU 시간 정렬, 독립 승인 작업 정보, 정상 고부하 대조군 및 새 가족별 시험을 요구한다. 이번 실험은 모델 학습·export·운영 적용을 수행하지 않았다.

CPU 평균의 분모는 작업 준비 확인부터 부모의 마지막 읽기까지 실제 경과 시간이다. 1초 종료 확인 간격 때문에 끝부분의 유휴 시간이 포함될 수 있으며, 이 측정은 task의 정확한 계산 구간과 같지 않다. 관측된 작은 점수 차이를 악성 의도의 증거로 해석하지 않는다. 임계값·혼동행렬 재현과 episode별 연속 구간 확인은 [재현 검증](results/cpu-context/reproduction_verification.json)에 기록했다.

### 다음 연구 방향

1. **기존 정상 전용 IsolationForest 학습 방식 재사용:** 저장소에는 이미 정상 syscall 트레이스만으로 IsolationForest를 학습하는 [train.py](../../train.py)가 있으며 [루트 README](../../../../README.md)도 이 파이프라인을 설명한다. 이 학습 아이디어를 출발점으로 역할·워크로드별 정상 기준과 정상 관리자 작업 대조군을 마련하고, 정상 기준에서 벗어나는 행동을 평가하는 방향을 권장한다.
2. **맥락으로 연결한 위험 증거 평가:** 민감 파일 확인 같은 선행 행동만으로 경보를 내지 않고, 검증된 task 계보에서 후속 위험 관측과 연결하는 방향을 연구한다. 정상 관리자 작업의 맥락과 대기·반복을 함께 대조한다. 기존 행동 기억 probe의 제한된 연결 검증만으로 이 확장이 완료됐다고 주장하지 않는다. 파일 열기·연결 시도만으로 실제 읽기·유출·사람의 악의를 추론하지 않는다.
3. **새 공격 계열의 블라인드 시험:** 이번 결과는 개발 근거로 남기고, 다음 모델·특징·보정 규칙을 고정한 뒤 아직 보지 않은 별도 공격 계열과 정상 역할 자료로 DR/FPR을 측정한다. 현재 시험 점수에 맞춰 알고리즘이나 임계값을 추가 튜닝하지 않는다.

재사용에는 입력과 점수 경로의 호환성 검증이 필요하다. 기존 `train.py`의 입력은 syscall map의 `vocab_size` 차원으로 정규화한 syscall 빈도이며, 이상 점수는 `-model.score_samples(...)`다. 현재 버킷 탐지기는 26개 집계 특징에 `predict_proba(...)[0, 1]`을 사용한다. 따라서 기존 IsolationForest pickle을 현재 버킷 탐지기에 그대로 넣을 수 없다. 어떤 특징 공간과 추론 경로를 재사용할지 확인하고, 그 입력에 맞는 학습·보정·검증을 계획해야 한다.

기존 `train.py`는 뒤쪽 20% 정상 트레이스로 임계값을 정하고 같은 자료에서 `measured_fpr`을 계산한다. 이 값을 독립 시험 FPR로 해석하지 않는다. 후속 평가에서는 정상 학습 세션, 정상 전용 임계값 보정 세션, 새 정상·미학습 공격 계열의 블라인드 시험 세션을 따로 확보하고 세션 전체로 분리하는 계획을 권장한다.

이 항목들은 기존 알고리즘과 학습 아이디어를 재사용하는 후속 연구 제안이다. 이번 작업에서 새 알고리즘을 선정하거나 탐지기를 구현·적용하지 않았으며, 현재 시험 결과에 맞춘 추가 튜닝도 하지 않았다.

## 데이터와 라벨 정책

정상 워크로드와 안전하게 제한한 기법 모사 유닛을 섞어 수집했다. 기법 모사 유닛 29개 중 23개는 단독으로 경보를 요구하지 않는 precursor-normal, 6개는 양성 모사로 분류했다. 양성도 더미 파일과 제한된 연결 시도 등 실험용 동작이며 실제 침해 성공을 뜻하지 않는다. 정상 워크로드는 이 29개와 별도로 포함된다.

현재 라벨 정책은 기존 모델 학습 때의 정책과 다르다. 따라서 기존 모델을 재생할 때의 오탐에는 현재 정책이 정상으로 분류하는 선행 행동도 포함된다. 사람이 공격자인지 관리자인지를 라벨이나 syscall만으로 판정했다고 주장하지 않는다.

평가 단위는 **1초 버킷**이다. 한 공격이 여러 버킷을 만들 수 있으므로 버킷 DR/FPR은 사건 단위 탐지율, 사용자 단위 오탐율, 운영 환경 FPR과 다르다. 유실된 세션이나 라벨 경계를 안전하게 판단할 수 없는 데이터는 성능 숫자를 채우기 위해 포함하지 않는다.

## 행동 기억: 실제 대기와 반복 검증

행동 기억은 RandomForest와 분리된 실험용 관측 도구다. 기본 증거 보관 시간은 1시간이고 추적 task 상한은 4,096개다. 수집기의 선택 옵션 `--fork-identities`가 켜져 있으면 typed fork hook에서 자식 PID·TGID·task 시작 토큰을 내보내고 유효성 플래그 `1 << 11`을 붙인다.

독자는 플래그가 있는 leader-to-leader fork만 받아들이며, 후속 자식 이벤트의 cgroup·PID·TGID·시작 토큰을 정확히 맞춘다. `ppid`, 명령 이름, 처음 나타난 PID나 시각 근접성으로 계보를 추정하지 않는다. task 시작값과 이벤트 시각은 서로 다른 clock domain일 수 있으므로 비교하지 않는다. 플래그 없는 기존 캡처는 직접 같은 task의 증거만 연결할 수 있다.

관측된 부모가 살아 있는 동안 파일 열기 증거를 만든 leaf 자식이 종료해도 가족 증거를 보관한다. 같은 검증된 계보의 후속 연결 시도를 만나면 `verified_task_lineage` scope로 `BEHAVIOR_REVIEW`를 기록한다. 직접 같은 task의 쌍은 `direct_same_task_only`로 구분한다. 증거는 한 episode 뒤 소비되므로, 같은 부모 아래 새 파일 열기·연결 쌍이 생기면 다시 검토된다.

실제 probe는 더미 credential 파일을 사용했으며 첫 쌍에 실제 600초 대기, 후속 새 쌍에 10초 대기를 포함했다. [probe 조건](behavior-validation/probe.json), [식별자 확인](behavior-validation/identity_audit.json), [재생 출력](behavior-validation/advisories.jsonl)을 보존했다.

| 관측 항목 | 결과 |
| --- | ---: |
| `BEHAVIOR_REVIEW` | 2개, 모두 `verified_task_lineage` |
| 검증된 fork 관계 | 7개 |
| 전체 이벤트 프레임 / HEALTH 프레임 | 950 / 615 |
| 시간 역전 초기화 / 유실 초기화 | 0 / 0 |
| precursor 없는 관리자 연결 대조 행동 | 1개, review 없음 |
| credential 파일 열기 hook | 3개 |
| 후속 연결 없이 부모 종료 때 폐기한 증거 | 1개 |

이는 대기와 반복을 포함한 특정 관측 쌍을 연결했다는 검증이다. probe 이전 모델의 대기·반복 탐지율이나 전체 관리자 작업의 오탐율은 측정하지 않았다.

파일 열기 LSM hook의 정상 반환과 읽기 모드는 **실제로 내용을 읽었다는 증명**이 아니다. 연결 이벤트도 성공 여부와 별개인 **연결 시도**이며 데이터 전송·유출이나 사람의 악의적 의도를 증명하지 않는다. 출력은 자동 차단이나 운영 `ALERT` 정책으로 승격하지 않은 advisory다.

스레드, 불확실한 식별자, 누락된 fork 정보, 관측된 부모 종료, 유실, 시간 역전은 보수적으로 증거를 폐기하거나 해당 세대를 제외한다. 보관 시간을 넘긴 증거와 상한 때문에 폐기한 상태는 coverage counter에 기록한다. 모든 길이의 `sleep`, 관측 범위를 벗어난 계보, 모든 공격을 처리한다고 보장하지 않는다.

## V2: 학습에 포함된 공격 유형의 새 세션 평가 완료

V2는 기존 유효 네 세션을 학습에 사용하고, 별도로 수집한 두 세션을 보정·시험에 각각 사용했다. 과거 V1의 보정·시험 세션도 이제 V2 학습 데이터에 포함되므로 이를 V2 독립 시험으로 다시 보고하지 않는다. 모델은 같은 300개 트리의 RandomForest, `random_state=42`, `class_weight="balanced"`, 26개 특징을 유지했다. 분할과 결과는 [V2 메타데이터](candidates/v2/meta.json), [평가 JSON](results/event_time_candidate_v2_20261006.evaluation.json)에 보존돼 있다.

| 용도 | 세션 수 | 정상 버킷 | 양성 버킷 | 합계 | 입력 |
| --- | ---: | ---: | ---: | ---: | --- |
| 학습 | 4 | 1,016 | 532 | 1,548 | 기존 `sessions/retry/`, `sessions/valid/` |
| 임계값 보정 | 1 | 254 | 134 | 388 | [verify_v2/session_1](sessions/verify_v2/session_1.event_time.npz) |
| 독립 시험 | 1 | 255 | 134 | 389 | [verify_v2_retest/session_1](sessions/verify_v2_retest/session_1.event_time.npz) |

보정 세션의 정상 254개 버킷만으로 임계값 `0.16666666666666669`를 정했다. 보정 정상 FPR은 1/254, 약 0.3937%였다. 보정 양성과 시험 점수로 임계값을 튜닝하지 않았다. 독립 시험은 **TP 133·FN 1·FP 0·TN 255, DR 99.2537%, FPR 0%**다. 남은 미탐 한 버킷은 `wiper_sim`이며 해당 유형은 31개 중 30개 버킷을 탐지했다.

이 시험 세션의 관측 FPR은 목표 0.5% 이하였지만, 정상 255개 버킷에서 오탐이 없었다는 결과가 운영 FPR 0%나 모든 관리자 작업의 안전성을 보장하지는 않는다. 공격 유형을 학습에서 제외한 시험도 아니다.

### 수집 품질과 재시도

처음 새 시험용으로 수집한 세션은 **writer queue에서 41,495건이 유실**돼 전체를 거부했고 NPZ를 생성하지 않았다. 이 실패 원인은 커널 ring buffer 유실과 구분한다. [V2 수집·평가 계획](event_time_v2_run_plan.json)에 따라 writer queue 용량을 늘려 재수집했으며, 특징·라벨·모델 설정·임계값 보정 규칙을 바꾸지 않았다. 유실 세션은 점수 산출이나 튜닝에 쓰지 않았다.

최종 채택한 보정·시험 세션은 각각 93개 유닛을 완료했고, writer queue·priority 및 커널 ring buffer의 실제 이벤트 유실 카운터는 모두 0이었다. 다만 두 세션에 **선택적 socket metadata 누락이 각각 1건** 있어 unknown으로 보존했다. 이벤트 유실 0과 metadata 완전성은 같은 주장으로 취급하지 않는다. 근거는 [보정 manifest](sessions/verify_v2/session_1.manifest.json), [보정 network audit](sessions/verify_v2/session_1.network.audit.json), [시험 manifest](sessions/verify_v2_retest/session_1.manifest.json), [시험 network audit](sessions/verify_v2_retest/session_1.network.audit.json)다.

### 같은 새 시험셋에서 기존·V1·V2 비교

[동일 시험셋 비교 JSON](results/event_time_same_test_comparison_20261006.json)은 같은 389개 버킷과 현재 라벨 정책으로 세 모델을 비교한다. 각 모델의 저장된 임계값을 사용했다.

| 모델 | 임계값 | TP | FN | FP | TN | DR | FPR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 기존 bucket-data9 재생 | 0.67 | 63 | 71 | 43 | 212 | 47.0149% | 16.8627% |
| V1 후보 | 0.17333333333333337 | 133 | 1 | 0 | 255 | 99.2537% | 0% |
| V2 후보 | 0.16666666666666669 | 133 | 1 | 0 | 255 | 99.2537% | 0% |

**이 시험에서는 V1과 V2가 동률이다. 과거 다른 시험셋의 V1 FPR 2.0%와 이번 V2의 0%를 직접 비교해 V2의 개선으로 해석하지 않는다.** 새 세션 일반화와 학습하지 않은 공격 유형 일반화도 구분한다.

### 추론 경로 검증과 적용 상태

[V2 runtime 검증 JSON](results/v2_runtime_verification.json)은 V2 시험 버킷 389개가 모두 일치하고 추가 runtime 버킷은 0개이며, 실제 모델 입력이 26개 특징임을 기록한다. TP 133·FN 1·FP 0·TN 255도 저장된 평가와 일치한다. 이는 같은 시험 입력에 대한 추론 경로 일치 확인이며, 새로운 독립 성능 측정이 아니다. V1의 384개 버킷 검증 기록을 덮어쓰지 않고 두 증거 파일을 분리해 보존한다.

`candidates/v2/`의 모델·메타데이터와 오프라인 평가는 완료됐다. 독립 검토의 승인 범위는 통제된 그룹 제외 평가 결과와 한계의 보고이며, 운영 성능이나 V2 적용의 승인이 아니다. **이번 실험 후보 중 shadow에 적용된 모델은 V1뿐이다. V2는 오프라인 결과물로만 보존하고 새 shadow 감시를 추가하지 않는다.** 알려진 유형에서는 V1과 동률이고 미학습 공격 탐지의 핵심 목표를 달성하지 못했기 때문이다. V1 기준 모델을 유지하며 기존 주 탐지기를 교체하지 않았다. 이번 문서 갱신으로 자동 수집·점검·학습 일정은 추가하지 않았다.

## 파일과 오프라인 재현

| 위치 | 내용 |

| `results/` | V1·V2 평가, 동일 새 시험셋 비교, V2 runtime 일치 검증, 미학습 그룹별 진단 RF 및 정상 전용 IsolationForest 평가 |

아래 명령은 이 디렉터리에서 동봉된 `src/` 스냅샷으로 실행한다. `capture.bin`과 `capture.bin.zst`는 별도로 준비한 캡처를 가리키는 예시 이름이다. 수집하거나 서비스를 시작하는 명령은 포함하지 않는다.

모델 재현에는 저장 당시 버전인 Python 3.10 환경, NumPy 2.2.6, scikit-learn 1.6.1, joblib 1.6.0을 기준으로 한다. 행동 기억 자체는 Python 표준 라이브러리만 사용한다. 모델 pickle은 신뢰할 수 있는 파일만 읽는다.

```bash
# 소스 스냅샷의 합성 프레임 회귀 확인
python3 src/test_behavior_memory.py

# 보존된 V1 후보의 오프라인 버킷 추론
python3 src/detect2.py --model candidates/v1 \
  --map ../bucket-data9/syscall_map_x86_64.json --input capture.bin --quiet

# 완료된 V2 후보의 오프라인 버킷 추론
python3 src/detect2.py --model candidates/v2 \
  --map ../bucket-data9/syscall_map_x86_64.json --input capture.bin --quiet

# 원시 캡처의 행동 기억 재생: 운영 탐지 정책 변경 없음
python3 src/behavior_memory.py capture.bin \
  --retention-sec 3600 --max-tasks 4096 > replay.behavior.jsonl

# 압축 캡처도 별도 원시 디스크 복사 없이 읽을 수 있다
zstd -dc capture.bin.zst | python3 src/behavior_memory.py - \
  --retention-sec 3600 --max-tasks 4096 > replay.compressed.behavior.jsonl
```

학습·보정·독립 시험을 다시 실행할 때는 보존된 `candidates/v1/`과 `candidates/v2/`를 덮어쓰지 않는 새 출력 위치를 지정한다. 아래 출력 디렉터리가 이미 있으면 다른 새 이름을 사용한다.

```bash
mkdir -p reproduction
# V1: 기존 네 세션 중 두 세션 학습, 한 세션 보정, 한 세션 시험
python3 src/evaluate_event_time.py \
  sessions/retry/*.event_time.npz sessions/valid/*.event_time.npz \
  --model-dir ../bucket-data9 --target-fpr 0.005 \
  --export-candidate reproduction/v1 > reproduction/v1.evaluation.json

# V2: 기존 네 세션 학습, 새 보정·시험 세션 각각 하나
python3 src/evaluate_event_time.py \
  sessions/retry/*.event_time.npz sessions/valid/*.event_time.npz \
  sessions/verify_v2/session_1.event_time.npz \
  sessions/verify_v2_retest/session_1.event_time.npz \
  --model-dir ../bucket-data9 --target-fpr 0.005 \
  --export-candidate reproduction/v2 > reproduction/v2.evaluation.json
```

export 명령은 세션 ID를 정렬한 뒤 마지막 두 세션을 각각 보정·시험으로 분리하므로 입력 파일의 단순 나열 순서로 분할을 정하지 않는다. 재현 출력의 분할 ID가 보존된 메타데이터와 일치하는지 확인해야 한다. 위 명령은 기존 공격 유형의 재현용이며, 미학습 그룹 평가의 결과를 대신하지 않는다.
